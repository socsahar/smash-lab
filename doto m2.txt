5. RISKS & BUGS CHECKLIST
================================================================================

🔴 CRITICAL RISKS
-----------------

A. DUPLICATE DATA ENTRY
✅ CONFIRMED BUG
Location: order.html (line 56) + waiver.html (line not visible)
Impact: User frustration, abandonment, typo discrepancies
Example: Email entered in order.html → entered AGAIN in waiver.html

B. LOSING CART ON LOGIN
⚠️ POTENTIAL BUG
Issue: localStorage.currentOrder NOT linked to user ID
Scenario: User starts order → logs in → currentOrder still exists BUT 
         not associated with smashlabs_current_user.id
Impact: If user logs in mid-checkout, order data persists but isn't 
       saved to their account

C. OFFER/POINTS NOT APPLIED
✅ CONFIRMED MISSING
Not found: points, credits, discount, promo in any checkout files
Impact: No incentive to create account or stay logged in

D. INCORRECT REDIRECT LOOPS
⚠️ LOW RISK
Current: No auth guards = no redirect loops
However: payment.html (line 272) redirects to order.html if no currentOrder
Concern: What if user refreshes payment page after clearing localStorage?

E. BACK BUTTON BREAKS STEP ORDER
✅ CONFIRMED ISSUE
Location: payment.html (line 392) goBack() confirms "you'll need to sign waiver again"
Why: Waiver data stored in localStorage.currentOrder.waiver - if user goes back, 
     it might be overwritten
Impact: User might lose waiver signature if they edit order form

🟡 MODERATE RISKS
-----------------

F. SESSION EXPIRY MID-CHECKOUT
Not verifiable: No JWT expiration logic found in client code
What happens: User stays "logged in" via sessionStorage until tab closes
Missing: Server-side session validation, token refresh logic

G. EMAIL MISMATCH BETWEEN STEPS
Scenario: 
  - Order email: user@gmail.com
  - Logged-in email: user@work.com
  - Waiver email: user@yahoo.com (typo!)
Current behavior: System accepts all three, no validation
Should: Warn "This email doesn't match your account"

H. NO "SAVE FOR LATER" / CART ABANDONMENT RECOVERY
- Orders only in localStorage.currentOrder - lost if user clears browser data
- No server-side draft orders
- No "resume your order" email reminders

6. RECOMMENDATIONS (TEXT ONLY - NO CODE)
================================================================================

🎯 PRIORITY 1: Fix Duplicate Data Entry (Quick Win)
----------------------------------------------------
Problem: Waiver form asks for name/email/phone that were already provided 
        in order form

Solution Description:
- In waiver.html, when page loads, check localStorage.getItem('currentOrder')
- If order data exists and has email, name, phone:
  * Pre-fill waiver form fields with those values
  * Make fields read-only with message "From your order"
  * Add small "Edit" button that redirects back to order page if they need 
    to change
- This eliminates re-entry and ensures data consistency

Expected Outcome: User fills form once, waiver auto-populated

Files to modify:
- waiver.html (add JavaScript onload)


🎯 PRIORITY 2: Make Login Valuable (Medium Effort)
---------------------------------------------------
Problem: Logged-in users get ZERO benefit - still must re-enter all data

Solution Description:
- In order.html, add JavaScript at top:
  * Call window.UserAuth.getCurrentUser() (already exists in user-auth.js)
  * If user exists, pre-fill #booking-name and #booking-email with 
    user.name and user.email
  * Add visual indicator: "Ordering as [user.email]" with small logout link
  * Make email field read-only (they can logout to change)
  
- In waiver.html:
  * Same logic - pre-fill from logged-in user
  * Show "Signed as [user.name]" confirmation
  
- In payment.html:
  * Show "Thank you, [user.name]!" personalization

Expected Outcome: Logged-in users save 5+ form fields, incentivizing 
                 account creation

Files to modify:
- order.html (add pre-fill logic)
- waiver.html (add pre-fill logic)
- payment.html (add personalization)


🎯 PRIORITY 3: Add "Login or Continue as Guest" Decision Point (High Impact)
-----------------------------------------------------------------------------
Problem: No clear guidance when user should login vs continue as guest

Solution Description:
- Add new step BEFORE order form (or as modal overlay on order page)
- Present two clear paths:
  * Path A: "Login / Sign Up" → faster checkout, order history, loyalty points
  * Path B: "Continue as Guest" → no account needed, email confirmation only
- If guest chosen, show one-time message: "You'll need to re-enter info 
  next time. Create account after checkout?"
- Place this decision at order.html top, NOT buried in navigation

Expected Outcome: Users consciously choose, reducing confusion

Files to create/modify:
- order.html (add decision modal)
- New component: login-or-guest-modal.html (optional)


🎯 PRIORITY 4: Link Orders to User Accounts (Backend Required)
---------------------------------------------------------------
Problem: Orders stored only in localStorage, not associated with user ID 
        in Supabase

Solution Description:
- When order completed in payment.html:
  * Check if sessionStorage.smashlabs_current_user exists
  * If yes, get user.id
  * Save order to Supabase orders table with columns:
    - order_id (from localStorage)
    - user_id (from session, NULL if guest)
    - order_data (JSON with all details)
    - status (paid/pending/cancelled)
    - created_at
  * For guests, user_id = NULL but store email for lookup
  
- Add new page my-orders.html (login required):
  * Query orders WHERE user_id = current_user.id
  * Display order history, reorder buttons

Expected Outcome: Users can view past orders, reorder with one click

Files to create/modify:
- Supabase: CREATE TABLE orders (...)
- payment.html (add save-to-database logic)
- my-orders.html (NEW FILE)
- Add "My Orders" link to navigation when logged in


🎯 PRIORITY 5: Add Validation for Email Consistency (Low Effort)
-----------------------------------------------------------------
Problem: User can enter different emails at each step without warning

Solution Description:
- In waiver.html, when email field loses focus:
  * Get orderEmail from localStorage.currentOrder.email
  * Get loggedInEmail from sessionStorage.smashlabs_current_user.email
  * If waiver email ≠ orderEmail OR ≠ loggedInEmail:
    - Show yellow warning banner: "This email doesn't match your order/account. 
      Confirmation will be sent here."
    - Require checkbox: "I confirm this is correct"
- Don't block submission, just make user acknowledge discrepancy

Expected Outcome: Reduces typos, ensures confirmation emails reach user

Files to modify:
- waiver.html (add email validation logic)


🎯 PRIORITY 6: Add Points/Loyalty System (Future Enhancement)
--------------------------------------------------------------
Problem: No incentive to create account beyond "convenience"

Solution Description:
- Create Supabase table user_points:
  * user_id
  * points_balance
  * last_earned_date
  
- Award points at order-success.html:
  * If logged in: +10 points per ₪100 spent
  * Display: "You earned 25 points! Total: 125 points"
  
- At payment.html:
  * If logged in + has points: show "Redeem 100 points for ₪10 discount" checkbox
  * Deduct from total if checked
  
- Add points display to navigation when logged in: "יציאה | 125 נקודות"

Expected Outcome: 40-60% increase in account registrations (industry standard)

Files to create/modify:
- Supabase: CREATE TABLE user_points (...)
- order-success.html (award points logic)
- payment.html (redeem points UI)
- js/user-auth.js (show points in nav)

7. CLARIFYING QUESTIONS
================================================================================

Based on current codebase analysis, here are critical questions to validate 
assumptions:

Q1: Is there any server-side session validation for the JWT token stored in 
    sessionStorage.smashlabs_admin_token?
    
    Context: Only found client-side storage, no token expiration checks
    Impact: If server validates tokens, client needs refresh logic

Q2: Do you want logged-in users to be REQUIRED to checkout with their 
    registered email, or allow them to use different email?
    
    Context: Affects whether order email field should be locked vs editable
    Impact: Determines validation strictness

Q3: Should guest users be prompted to create account AFTER successful checkout 
    (convert funnel)?
    
    Context: No post-checkout signup flow found
    Impact: "You just saved ₪150! Create account to track this order and 
           earn points"

Q4: Are there any existing analytics tracking which step users abandon most?
    
    Context: Would help prioritize which flow to optimize first
    Impact: If 60% abandon at waiver, prioritize that step's UX

Q5: Is the Stripe integration in .env active, or is this still using 
    simulated payments?
    
    Context: payment.html (line 362) shows setTimeout simulation
    Impact: Real Stripe flow might have different auth requirements
